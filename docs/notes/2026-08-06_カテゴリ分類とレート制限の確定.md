## 2. FVACのカテゴリ分類：NPO法別表の全国共通20分野で確定

かもちゃんがFVACサイトを確認した結果、FVAC独自の分類ではなく特定非営利活動促進法（NPO法）別表の全国共通「20分野」をそのまま使用していることが判明。FVAC登録団体ページでも「01 保健、医療又は福祉の増進」のように番号付きで表記されている。

登録画面（`docs/notes/mockups/circle_intake_form.html`）のFVAC用カテゴリ選択肢を、この20分野（番号付き）に更新した。「その他」自由記述欄は残し、20分野に当てはまらない記載のための逃げ道として維持。

## 3. 公民館のカテゴリ分類：輝きの流用をやめ、当面は自由記述のみに変更

かもちゃんの調査により、公民館サークル（200件超）は「サークル案内」冊子ベースで案内されており、輝き・FVACいずれとも異なる分類体系の可能性が高いことが判明（市サイトはbot検知のため確証は取れず）。

前稿では「輝きの7分類を暫定流用」としていたが、これを撤回。**公民館は登録元固有の選択肢を出さず、「その他」自由記述のみで受ける**方針に変更した。実物の「サークル案内」を入手できたタイミングで正式な分類を検討する。

## 4. レート制限：1IPあたり1日20件・ソフト制限で確定

現場スタッフ中心の内輪ツールという前提のもと、1IPあたり1日20件を目安値として採用。正規の登録作業で1人が1日20団体も新規登録することは想定しにくいため、実運用を妨げずボット的な連投のみを弾ける値と判断。

**運用方式はハードブロックではなくソフトフラグ**とする：20件を超えても登録自体は拒否せず保存し、`raw_circle_submissions`側に超過した旨のフラグを立て、後でまじまじさんが確認できるようにする。

### スキーマへの影響（要合意）
現行の6テーブルスキーマには超過フラグを持つカラムがないため、`raw_circle_submissions`に列追加が必要:

```sql
ALTER TABLE raw_circle_submissions ADD COLUMN flagged_reason TEXT;
-- 例: 'rate_limit_exceeded'。NULLなら平常。raw_fieldsはあくまで提出データそのものの
-- コピーとして扱い、システム由来のフラグは混在させない方針とした。
```

登録画面・レビュー画面のUI文言は「本日の登録N件（目安20件、超過時は自動フラグ）」に更新済み。

## 5. APIドラフト（更新版・レビュー依頼）

前稿からレート制限の扱いをソフトフラグ方式に修正した。

```
POST /api/auth/login          { name, passcode } → セッショントークン（短命）
POST /api/submissions         { organization_type, raw_fields... }
                               → raw_circle_submissions に1行追加
                                 サーバー側でsubmitted_by/IP/timestampを付与
                                 同一IPの本日件数が20件を超えていてもブロックせず保存し、
                                 flagged_reason='rate_limit_exceeded' を設定
GET  /api/submissions?status=pending|returned|approved&flagged=true
                               → レビュー画面の一覧用。flagged=trueで超過分だけ絞り込み可能
GET  /api/submissions/:id     → 詳細＋類似circle候補（サーバー側でname突き合わせ）
POST /api/submissions/:id/approve
     { mode: "new" }
     | { mode: "link", target_circle_id, self_reported_confirmed: true }
                               → circlesへ正規化。linkモードはself_reported_confirmed必須
                                 （フロントのチェックボックスに加え、サーバー側でも強制）
POST /api/submissions/:id/return
     { reason }                → 差し戻し（circlesへは反映しない）
```
