## 1. トップ画面（index.html）：地図を一番上に表示

これまで提案バナー（輝き市民サポートセンターとの連携イメージ）が地図より先に表示されており、訪問者が地図に辿り着くまでにスクロールが必要だった。`<main>`（凡例＋地図）を`<header>`直下に移動し、提案バナーはその下に配置する順序へ変更した。

## 2. 団体登録画面：モバイル最適化（第4稿）

かもちゃんから「登録画面がスマホ最適化されていない」との指摘を受けて調査した結果、`docs/notes/mockups/`配下のファイルには `<meta name="viewport">` を含む `<head>` が存在しなかったことが判明した（Claude Artifactとして公開する際はプラットフォーム側が自動でラップするため気づきにくかったが、GitHub Pages上の生ファイルとして開くと、モバイルブラウザがデスクトップ幅で縮小表示してしまう状態だった）。

### 修正内容
- `docs/notes/mockups/` 配下の2ファイルに、`<!doctype html><html><head><meta charset><meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover"></head><body>...</body></html>` の正しいラッパーを追加（Artifact公開用の本体ファイルはプラットフォームの自動ラップに委ねる方針のまま、リポジトリ配下のコピーだけ独立して正しいスタンドアロン文書にした）
- 登録画面のレイアウトを2カラム（フォーム＋常時表示のサイドパネル）から1カラムに変更。モバイルでは元々サイドパネルがフォームより先に表示される構成になっており（`order:-1`）、フォームより先に生データJSONが目に入る分かりにくい構成だった
- 入力欄・チップ・ボタンのタッチターゲットを拡大、レート表示チップの折り返し不具合（`flex-wrap`未指定で横はみ出し）を修正
- 保存ボタンをスティッキーの操作バーに固定し、`env(safe-area-inset-bottom)` でiPhoneのホームインジケーターとの重なりを回避

## 3. 確認画面フローの追加

「重複候補」「raw_fields プレビュー」を常時表示のサイドパネルから外し、**「内容を確認する」ボタンを押した後に表示される確認画面**に変更した。

### 新しい画面遷移
1. フォーム画面（1〜6のセクション、常時表示のプレビューなし）
2. 「内容を確認する →」を押すと確認画面へ遷移
   - 入力内容のサマリ（読みやすい形式）
   - 重複候補（変更なし、統合は本人確認が原則のまま）
   - raw_fields JSONプレビュー（内容は変更なし、表示タイミングのみ変更）
   - 「← 戻る」で フォーム画面に戻れる（入力内容は保持される）
3. 「この内容で保存する」を押すと保存完了画面へ（モックアップのため実際の保存は行わない）

実装上のバグとして、確認画面のCSSに `display: flex` を無条件指定していたため、`hidden` 属性だけでは画面が隠れない不具合があった。`.confirm-view[hidden] { display: none; }` を追加して修正した（ブラウザで実機確認して発見）。

## 4. 動作確認

Claude Browser でモバイル幅（375×812）・ライト/ダーク両テーマにて、ゲート→フォーム→確認画面→保存完了画面の一連の流れをクリック操作で確認した。横スクロールの発生や要素の重なりは見られなかった。
